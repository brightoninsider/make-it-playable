Make it playable.

Turn an idea into a small game someone can actually play, judge, and improve—before polish, systems, or expensive art take over.

A game is more than a beautiful screen.

Agree what success looks like, then start with a small playable loop: an input, a decision, a consequence, and a retry. Your agent playtests, compares the result with those checks, fixes the largest gap, and tests again. One local progress link and a short record keep your feedback and decisions intact between sessions.

The guide and starter need no account, service, remote font, CDN, or analytics. Building your game needs a capable coding agent with file and workspace access, suitable tools and art assets, time, and your feedback. The skill guides that work; it cannot guarantee a particular visual finish or a fun game.

Start

Name the first minute.

What will someone do, feel, or learn? Agree the player’s goal, device targets, and visible checks that will tell you the game is ready.

Build

Play it. Picture it.

Try an early playable loop beside a visual mockup or gameplay image. Give focused feedback, refine the look, then bring the final assets into the actual game.

Review

Play, fix, repeat.

Compare the running game with the look you accepted. Playtest, check, fix, and repeat until the agreed checks pass. A missing review or real blocker stays visibly incomplete.

An available image generator can help explore a look or make assets; visuals drawn directly in code can be the finished style too. Once you accept the core play and visual direction, the agent improves assets and detail in small passes, comparing the same views and preserving your choices. A beautiful mockup and a game that feels good to play need separate reviews. Expect to steer the brief, review the first play and look, and judge the final play, art, and sound. More feedback may be needed when a decision changes; the agent works independently between available checkpoints.

A finished small starter, ready to change.

The starter is a deliberately modest Canvas collect-and-avoid game. It already has keyboard, pointer, and touch input; labelled goal and gauges; Start, Pause, mute, win, fail, retry; reduced-motion behaviour; gesture-only audio; deterministic seeded simulation; fixed-step rendering; and Node tests.

About the soft 5 MB target. Measure encoded browser responses required to start real gameplay—not just a menu shell. Keep that initial set below 5 MB when practical; report later levels, endings, and optional assets separately. It becomes a hard cap only when the project asks for one.

Choose tools for the game, not the habit.

The skill guides your coding agent in choosing and using tools such as Godot, Blender and Three.js. These tools are optional and aren’t included in the download. Your agent checks what’s available and explains any installation or setup needed before using them. The agent can help with setup where its environment allows.

Canvas / DOM

Best first choice for compact 2D loops, interaction, and learning pieces. The included starter needs none of the optional tools below.

Three.js

A project library for real-time 3D space, lighting, or a camera that makes the experience. Add it only when needed; see the Three.js installation guide.

Godot

Use its engine and editor when scenes or systems add clear value. It is a separate app; browser exports also need matching export templates.

Blender

An optional separate app for 3D assets, not a runtime or default. It needs to be available to the agent; see Blender setup.

Image tools

Detect what is available. Use an authorized provider only when it materially helps; no provider, model, account, or price is assumed.

Automation

Use browser automation when the host already has it. Otherwise say so and test ordinary inputs by hand.

Before you call it done.

  • The first loop can be played with normal inputs.
  • The goal, gauges, controls, win, fail, and retry are clear.
  • Phone-sized and desktop views have been checked.
  • Keyboard, pointer, touch, focus, pause, mute, and hidden-tab return behave.
  • Essential play does not depend on sound, flashing, or reduced-motion effects.
  • Real assets have a rights basis and required attribution.
  • Human fun/art/listening feedback is recorded separately from technical checks.
  • The browser release is a checked allowlist, not a development folder.

Package it without publishing it.

The build script creates a one-folder ZIP, manifest, and checksum. It keeps private material, caches, evidence, and release artifacts out of the export. It does not upload or publish anything.
